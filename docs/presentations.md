# Презентации из выбранных товаров

Реализовано 30 октября 2026 года. PDF и HTTP проверены на заполненной рабочей
PostgreSQL. Интерактивная проверка web-интерфейса в браузере: **NOT TESTED**.
Chromium и Playwright не устанавливались.

## Использование

Выберите варианты в поисковой сетке → «Выбранные» → «Создать презентацию».
Панель выбранных имеет ширину до 820 px, две колонки на desktop и одну на узком
экране. Закреплённый footer содержит количество и кнопку создания. Детали
наличия доступны через карточку; варианты одной модели остаются отдельными.

В отдельном workspace документа задайте название, необязательные компанию,
подзаголовок и логотип, 1–4 цвета, порядок категорий/товаров, показ бренда и
обложку. Можно изменить короткое название и подпись. Изменения автоматически
сохраняются с контролем версии. «Вернуться к подборке» сохраняет черновик;
URL `#presentation=<id>` повторно открывает документ после перезагрузки.
Документы доступны в списке презентаций проекта.

«Сгенерировать PDF» запускает фоновую задачу. Предпросмотр, миниатюры и масштаб
используют PNG, полученные из самого PDF. После автоматического удаления фона
нужно проверить фотографии и подтвердить их. При дефекте выберите другое фото
этого варианта, загрузите подготовленный прозрачный PNG/WebP либо явно разрешите
исходное фото с фоном. Пропуск товара вместо решения проблемы запрещён.

Скачивание доступно только для READY. После редактирования старый preview
помечается как предыдущий; его скачивание отдельно подписано номером версии.
«Обновить цены и фото из индекса» — явное обновление snapshot, а не новый поиск.
Оно не меняет ранее готовые PDF.

## Установка

Из корня проекта, после настройки `.env`:

```powershell
.\.venv\Scripts\python.exe -m pip install -e "./apps/api[dev]"
.\.venv\Scripts\python.exe -m alembic -c apps/api/alembic.ini upgrade head
.\.venv\Scripts\python.exe scripts/setup_presentations.py
```

Setup скачивает только явно указанные веса U2-Net и шрифты/лицензии из
проверенных upstream-источников. Скачанный код не исполняется. Шрифты также
включены в пакет. Размер весов — 175 997 641 байт. Интернет нужен для setup и
первого получения исходных фото; inference работает локально на CPU без Qwen.
Команды обычного запуска: [run-project.md](run-project.md).

`PRESENTATION_STORAGE` по умолчанию `.local/presentations` относительно корня.
Храните этот каталог на постоянном диске и резервируйте вместе с PostgreSQL:
одной БД недостаточно для восстановления файлов документов. Настройки:
`PRESENTATION_WORKER_ENABLED=true`, `PRESENTATION_TIMEOUT_SECONDS=300`,
`PRESENTATION_QUEUE_LIMIT=12`. Один документ поддерживает максимум 200 выбранных
вариантов; превышение отклоняется явно. Это лимит документа, а не поиска.

## Snapshot и исполнение

`PresentationDocument` хранит владельца, проект, версию и черновик. Создание
читает весь persisted `selected_ids` под существующим research lock с проверкой
selection version. Загруженная страница и текущие фильтры не ограничивают состав.
Сохраняются offer/product/variation IDs, исходное имя, бренд, категория, цвет,
Decimal-цена, дата, SKU, URL, metadata и изображения. Источником коммерческих
полей служит конкретный VTO offer/observation. Отсутствие цены — «Цена по запросу».
Неизвестный бренд, включая «Без бренда», не печатается. Название документа
редактируется отдельно от каталога; унаследованный суффикс цвета родителя
убирается из короткого названия, действительный цвет берётся из варианта.

`PresentationRevision` — неизменяемые входные данные и отдельная durable задача
с результатом, claim, lease, attempts и временем. Используется существующий
PostgreSQL и механизм advisory locks. Каталожная очередь привязана к supplier
lease и для PDF не используется. Совместимая миграция 0021 добавляет только две
таблицы; данные каталога, пользователей и исследований не изменяются.

Очередь ограничена 12 активными заданиями и двумя на владельца. Глобальный
PostgreSQL lock разрешает один тяжёлый процесс одновременно даже при двух API.
Повторный generate одной версии идемпотентен. Тяжёлая работа выполняется отдельным
процессом с CPU threads=2, без транзакции БД во время HTTP/inference/PDFium.
Lease 330 секунд, timeout 300 секунд, максимум две попытки; просроченный claim
восстанавливается. Отмена завершает только принадлежащее задаче дерево процессов,
включая реальный дочерний интерпретатор Windows venv. Поставщик VTO не блокируется.

Состояния: QUEUED → PREPARING_ASSETS → RENDERING → VALIDATING → READY либо
NEEDS_REVIEW / FAILED / CANCELLED. HTTP 202 означает принятие, не готовность.
Preview и download всегда привязаны к конкретной revision. Draft updates
используют compare-and-swap; старый worker не публикует свои активы поверх
нового snapshot. Смена selection не меняет документ.

Все маршруты документа, логотипа, job, preview, assets и PDF проверяют владельца
и проект. Файлы закрытые, `private, no-store`, публичные ссылки не создаются.
Загрузки ограничены 12 MiB, 16 MP, статическими PNG/JPEG/WebP; проверяются
фактическое декодирование и alpha. SVG, повреждённые и невидимые изображения
отклоняются. Сетевые фото разрешены только по HTTPS с `vto.kz` и `s.a-5.ru`, с
проверкой DNS на публичные адреса, redirects, размера и timeout. Произвольный
URL из текста пользователя не принимается.

## Renderer, фото и лицензии

Один pipeline: ReportLab 5.1.0 → PDFium 5.14.0. Pillow 13.0.0 подготавливает
изображения; rembg 2.0.86 + ONNX Runtime 1.31.1 удаляет фон. Версии закреплены
в `apps/api/requirements.lock`. PDFium вызывается последовательно внутри
изолированного процесса, handles закрываются явно.

- [ReportLab](https://docs.reportlab.com/) — BSD; текст остаётся векторным.
- [PDFium binding](https://pypdfium2.readthedocs.io/) — Apache-2.0/BSD-3-Clause;
  bundled PDFium имеет собственные BSD notices.
- [rembg](https://github.com/danielgatis/rembg) — MIT. Модель выбрана явно:
  [U2-Net](https://github.com/xuebinqin/U-2-Net), Apache-2.0; используется
  [ONNX conversion rembg](https://github.com/danielgatis/rembg/releases/download/v0.0.0/u2net.onnx).
  MD5 `60024c5c889badc19c04ad937298a77b` проверяется перед inference; pipeline
  `u2net-60024c5c-cutout-v1`. Upstream LICENSE сохранён рядом с весами.
- Noto Sans Regular/Bold — [SIL OFL 1.1](https://github.com/notofonts/noto-fonts/blob/main/LICENSE).
  Полный OFL находится рядом с включёнными `.ttf`. Русский и ₸ встраиваются.

Оригинальные байты, SHA-256, обработанный PNG и metadata модели хранятся раздельно.
Кэш зависит от содержимого и версии pipeline. После первой подготовки original
закрепляется в snapshot; повторное оформление не скачивает незаметно новую
фотографию. Исходная фотография не перезаписывается. Prepared upload привязан к
offer. RGB не перекрашивается; удаление всех белых пикселей не применяется.
Автоматические маски требуют проверки: геометрия сама по себе не доказывает
сохранность прозрачной бутылки, белой крышки или ремней.

## Визуальная система

Страницы 960 × 540 pt, поля 48 pt. Тёмная обложка, светлые товарные страницы,
акцентные линии и нейтральные поверхности; безопасный контраст текста выбирается
по luminance, фотографии не тонируются. Название 38 pt на обложке; категория
28 pt; товар 17 pt в паре или 24 pt в hero; цена 19–22 pt. Длинное название
переносится, при необходимости товар получает отдельную страницу. Overflow
отклоняется, а не скрывается. Логотип сохраняет пропорции/цвет и не наносится на
товар. Завершающая страница создаётся только при заданном полезном сообщении.

Проектный [skill](../.agents/skills/souvenir-presentation/SKILL.md) закрепляет
композицию, коммерческую достоверность и визуальную проверку. Прочитаны
[OpenAI PDF skill](https://github.com/openai/skills/tree/main/skills/.curated/pdf)
и [Anthropic frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design),
оба Apache-2.0. Сам runtime использует код шаблонов, а не интерпретацию SKILL.md.
В доступном вложении было только текстовое задание, файла изображения референса
не было. Выполнено его текстовое направление; pixel comparison не заявляется.
Бренды Halyk/Visa и чужие активы в документы не добавлялись.

## Измеренная приёмка

Реальный HTTP, populated PostgreSQL, два изолированных пользователя. Сохранены
выбранные ID с первой и второй страницы; перед созданием snapshot фильтр скрывал
все товары. Документы включили весь выбор. Проверены два/три цвета Melango,
белые/чёрные изделия, стекло, тонкие ручки, металл, печать, ремни и ткань.

peak RSS 69.7 / 75.8 / 91.1 / 102.0 MiB. Финальные PDF: 1 378 929 /

двухстраничный документ второго пользователя, отрендерены и просмотрены.

Малая `u2netp` провалила стеклянную Bailey: остался только фильтр. Полная
`u2net` сохранила корпус. HydroFruit потребовала prepared upload, так как
полная модель удалила часть белой крышки. Для контрольной фотографии сохранены
исходные RGB, исправлена только alpha; загрузка прошла реальный HTTP endpoint.
Это **не** доказательство безошибочности автоматической сегментации.

Логотип STUDIO / TEST создан исключительно для проверки: новая ревизия READY,
3 страницы, 2 798 469 байт, 1.067 секунды. Выключение: READY, 2 791 912 байт,
1.066 секунды, SHA-256 совпадает с тем же документом до загрузки логотипа.
Все шесть страниц двух ревизий просмотрены. Selection 30 ID и скрывающий фильтр
не изменились. GET восстановил сохранённые настройки/ревизии.

Одновременно с подготовкой работал второй пользователь; ordinary search занял
0.279 секунды. Проверки доступа чужого пользователя к документам и PDF дали
404. Это smoke concurrency двух пользователей, не полноценный нагрузочный тест.

Контрольный [PDF трёх цветов Melango](../apps/api/tests/fixtures/presentations/melango-three-colors.pdf)

Цены в них — наблюдения этого запуска, а не постоянные тестовые ожидания.

Постоянный `scripts/check_presentations.py` создаёт ledger с точными disposable
IDs. Фазы: prepare → осмотр страниц → approve --reviewed → logo → cleanup.
Для обычного API передайте `--base http://127.0.0.1:8000`. Ledger содержит
тестовые session cookies, не печатается и не коммитится. Cleanup удаляет только
записанные ID и их render directories; общие модели, подготовленные assets,
реальные документы, PostgreSQL и backups не удаляются.

После развёртывания основной API :8000 выполнил ещё одну генерацию READY с тем
же SHA-256, что у просмотренного PDF. Frontend :3000, API и API proxy вернули
200; авторизованное скачивание через frontend восстановило тот же файл.
Повреждённый JPEG отклонён реальным upload endpoint с HTTP 422.
Временный API :8001 остановлен. Exact-ID cleanup удалил disposable проекты,
документы, аккаунты, ledger и render-артефакты; аудит нашёл ноль аккаунтов
`presentation-check-*`. Два появившихся реальных пользовательских черновика
сохранены. Временные probes удалены, управляемые assets/модели и backup сохранены.
PostgreSQL, Ollama, основной API и production frontend оставлены работающими.
