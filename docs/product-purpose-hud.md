# Поиск основного изделия и HUD — 2026-10-30

Функциональная проверка: **PASS**. Визуальная проверка desktop/mobile в браузере:
**NOT TESTED**. Chromium/Playwright не устанавливались. Проверки относятся к
заполненной PostgreSQL `souvenir`, 4 371 предложению VTO и production API 8000.
Количество предложений не равно количеству физических моделей.

## Первопричины

Фактический путь: `/projects/{id}/requests` → ProjectQueryService → `grid_plan`
→ ProductBranch → `grid_conditions` → `grid_pool` → `grid_response` → DTO →
ResearchWorkspace/ProductCard.

1. Первый ошибочный допуск происходил при построении пула: категория семейства
   **ИЛИ** подстрока в названии считались достаточными. Упоминания содержимого,
   совместимости и деталей попадали в один ряд с основным изделием.
2. Прежний `handle_is_not_pen` исключал лишь несколько формулировок. Он не
   различал набор, футляр, коробку, блокнот с ручкой и самостоятельную ручку.
3. `product_view` по умолчанию присваивал `category_match=EXACT`, а карточка
   выводила точность через `match=exact`, относящийся к цвету. Точное совпадение
   цвета не подтверждало товарную категорию.
4. Существующий resolver не распознавал инструментальную форму «ручкой».
   Дополнены формы того же понятия, без списка исключений по моделям/ID.
5. На рабочей PostgreSQL с C locale `ILIKE` не сопоставлял кириллические
   «футляр» и «Футляр». Для явных ролей добавлена проверка начала слова с
   заглавной буквой, уже используемая обычными ветками.
6. Холодный live-запуск выявил коррекцию «блокнот» в постороннее каталоговое
   слово. Подтверждённая исходная связь основного изделия и дополнения теперь
   сохраняется при построении плана. Регрессия подставляет заведомо ошибочный
   результат коррекции и проверяет сохранение notebook + required pen.

## Определение основного изделия

`domain/product_purpose.py` использует существующий UniversalCategoryResolver.
Новый небольшой слой описывает отношения, а не отдельную товарную таксономию:
PRODUCT, HYBRID, SET, PACKAGING, ACCESSORY, COMPONENT, UNKNOWN.

Основное название до связки «с/для/в/без/with/for/without…» отделено от
упоминаний, совместимости и подтверждённого содержимого. Явные роли упаковки
или набора имеют приоритет над широкой категорией VTO. Название модели может
получить тип из структурированных характеристик или непротиворечивой категории.
Категория, названная только как связанный объект, такого доказательства не даёт.
Подтверждённый состав извлекается из названия, соответствующих характеристик
и явно обозначенного состава в описании; совместимость чехла не является его
содержимым. Читается ограниченный фрагмент описания, до 2 000 символов.

Гибрид требует подтверждения нескольких функций: 2-в-1, многофункциональность,
составное наименование функций или ручка с вечным карандашом. Произвольный
дефис и цветовой суффикс не доказывают гибрид. Именно дополнительная проверка
полного пула обнаружила «Сумка … без ручек»: отрицательное упоминание и дефис
раннего варианта классификатора больше не превращают сумку в ручку.

Для каждой карточки передаётся `purpose_match`: принятое решение, реальная
категорийная метка, причина, роль/основные понятия/содержимое и provenance.
RELATED/REJECTED не получают надпись «Точное совпадение» через цвет.
Явно включённые наборы маркируются RELATED и при обычной релевантности идут
после самостоятельных изделий. Режим Case/allocator не возвращался.

SQL остаётся генератором кандидатов. Проверяется весь скалярный пул до facets,
total, сортировки и страницы. Product DTO гидратируются только для страницы
и выбранных. Новые записи VTO проходят ту же проверку при последующем поиске;
изменение исходных полей меняет ключ ограниченного кэша классификатора.

Версия `primary-product-v2` хранится в производном ResearchSession. Старое
исследование при открытии обновляется под существующим mutation lock:
`REVALIDATE_PRODUCT_PURPOSE`, предыдущие IDs/ветки/intent/view в history,
новая версия представления. Сообщения и выбор сохраняются; выбранный товар,
переставший соответствовать запросу, остаётся доступен с REJECTED.
Цены, stock, external IDs и времена коммерческих observations не изменяются.

## HUD и карточки

Над сеткой размещён ResearchHud: слева реальные фильтры, справа отдельный
блок выбранных, CSS `minmax(0,4fr) minmax(150px,1fr)` с переносом полей.
Бренд раскрывает поиск с множественным выбором, далее цвет, материал, размер,
цена от/до и тираж. Числовые поля отправляются после 300 мс; остальные меняют
состояние сразу. Плашки различают исходные условия и дополнительные фильтры.
Reset виден при наличии дополнительных условий и не снимает исходные требования.
На узких экранах используется существующая мобильная панель фильтров и отдельный
вертикальный блок выбранных. Общая тема и сетка сохранены.

Удалены старый dropdown соответствия, toolbar-кнопка выбранных, Undo, Continue
и счётчик источников. Выбор использует прежние server view/selected_ids; справа
видны общий счётчик и скрытые выбранные. Настройка моделей/вариантов компактна.
Блок выбранных доступен и при пустом результате. В карточке удалены внешний
footer и иконка поверх фото; изображение, checkbox и внутренние кнопки деталей
остались. Source URL и SKU сохранены в данных и details dialog.

Записи view отправляются последовательно по серверной версии, быстрые правки
объединяются. Более ранний фильтр не публикуется под новым черновиком. При
конфликте допускается одна перезагрузка/повтор; смена проекта отсекает старый
ответ. Выбор не сбрасывает загруженные страницы, а сам по себе не инвалидирует
cursor. Изменение условий/порядка/состава результата по-прежнему его инвалидирует.

## HTTP acceptance и сохранность

`scripts/check_product_purpose.py` создаёт собственные аккаунты/проекты и
удаляет только их записанные IDs. Проверено на основном API после рестарта:

- PASS: две ветки, объединение без дублирования вариантов; красные в том же
  исследовании; исключённые типы не возвращаются фильтром.
- PASS: выбор с первой и второй страниц; фильтр Molti оставляет 3 товара,
  оба выбранных скрыты, но доступны в selected_products; чтение состояния
  после повторного GET сохраняет весь view. Это F5-контракт API, не браузерный F5.
- PASS: Undo через сохранённый API, reset, новый самостоятельный поиск и два
  пользователя; чужое исследование возвращает 404.
- PASS: чёрные ручки ≥300 — 28; reset бренда сохраняет BLACK и 300;
  чатовая смена на красные даёт 14, RED вместо BLACK, тираж 300 сохранён.
- PASS: обновление старого исследования сохраняет сообщения/selection/history.
  Проверены исходный допуск 434 → 288 на первой реализации и версия v1 → v2,
  288 → 287, с сохранённой `vto:1945068`, теперь REJECTED/hidden.
- PASS: инструментированный API без второго worker показал 0 VTO-запросов
  для поиска/фильтров. Ручные фильтры не проходят через Query Understanding/Qwen.
  Основной DTO также возвращает `supplier_http=0`.

В финальном прогоне первая страница гидратировала 100 объектов, красная — 27.
Проекция/страница делали 4 SQL-запроса. На инструментированном отдельном API
до финального рестарта измерено 23 SQL на создание research и 18 на чатовый
фильтр; это включает ownership/persistence. Объём первого ответа вырос с
187 526 до 225 891 байта из-за evidence; красного уменьшился со 108 396 до
71 519. Новый холодный поиск дороже baseline; ускорение и нагрузочный p95
не заявляются. Индекс остаётся единственным источником обычного поиска.

Во время финального acceptance число предложений осталось 4 371. Контрольный
MD5 по offer IDs, product IDs, source URL, image и полным ProductObservation
payload/observed_at до/после одинаков: `f27cc8d9f643572e4834240bce5b0e41`.
Importer/availability policy, schema и коммерческие данные не менялись.
Реальные пользователи и проекты не удалялись. Созданные acceptance-аккаунты
удалены по ID; read-only проверка их префиксов дала 0 оставшихся записей.

Существующий VTO job `3af11531-88ce-4c5f-b33d-869c4045d606` сохранён:
PENDING / TEMPORARILY_UNAVAILABLE, collection page 22, supplier lease NULL,
retry_after 2026-10-30 13:42:16 UTC. Это ранее возникший backoff источника,
не результат изменения поиска. Новый полный обход или второй worker не запускались.
Полнота каталога этой задачей не подтверждается.
