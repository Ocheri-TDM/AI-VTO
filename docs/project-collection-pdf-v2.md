# Проектная подборка и PDF Design V2

Позднее в тот же день Premium Dark обновлён до версии 3:
[визуальная доработка и сравнение до/после](premium-dark-refinement.md).
Ниже сохранён исходный отчёт Design V2; его эталоны и старые PDF не заменены.

Реализовано и проверено 30 октября 2026 года на заполненной PostgreSQL,
основном HTTP API и в установленном Microsoft Edge. Новые браузерные зависимости
и Chromium runtime в проект не добавлялись.

## Пользовательский сценарий

Выбранные варианты накапливаются в проекте: ручки → рюкзаки → бутылки.
Новый поиск, фильтры, история запросов и Undo не очищают подборку. Каждый цвет
одной модели остаётся отдельным вариантом. Удалить товар можно снятием выбора
или кнопкой «Убрать»; общая очистка требует подтверждения.

Панель доступна независимо от наличия активного research. Она читает все товары
проектной подборки, включая варианты из прежних поисков и других страниц.
Из неё создаётся отдельный документ. Возврат к поиску, F5 и смена проекта
сохраняют состояние; у другого проекта своя подборка.

В оформлении документа нет поля «Название». Внутреннее имя автоматически:
«Подборка для [компания]» либо «Каталог выбранных товаров». На обложке —
компания или нейтральное имя каталога, необязательный подзаголовок и товары.
Старые документы продолжают открываться. Названия отдельных товаров остаются
редактируемыми. Файлы называются безопасно: `presentation-vN.pdf`.

Доступны Editorial, Premium Dark и Modern Graphic, палитра, необязательный
логотип, порядок категорий/товаров и «Автодизайн · локальная Qwen».
«Другой вариант оформления» сохраняет новую версию дизайна. Обновление состава
из текущей подборки и обновление коммерческих данных — отдельные явные действия;
старые PDF остаются доступны со своими версиями.

## Причины дефектов и исправления

**Потеря выбранных.** Единственным хранилищем был `ResearchSession.view.selected_ids`.
NEW_SEARCH создавал другой research с пустым списком; панель использовала
`research.selected_products`. Новый источник истины — проектная коллекция.
Поля selection в research API сохранены как совместимая проекция, а не источник
самостоятельного пользовательского выбора. Старый полный replace принимается
только с актуальной версией коллекции и не создаёт поисковых Undo-записей.

**Перекрытие фотографий.** Это измерено в настоящем DOM: desktop-изображение
имело высоту 341 px при image-wrapper 228 px; mobile — 417 px при 250 px.
Grid с автоматическим минимальным размером и процентная высота изображения
позволяли intrinsic image size выйти из области. Исправлены сама структура и
геометрия: отдельный фиксированный `ImageArea`, ограниченная им кнопка,
`min-width/min-height:0`, `object-fit:contain`, информация и действия в нормальном
потоке. Изображение теперь 196 px внутри desktop-кнопки с внутренними отступами,
218 px на mobile. `z-index` текста не повышался; текст всей карточки не обрезается.

**Однообразие PDF.** Вместо обязательных одинаковых подложек введены общие
композиционные компоненты с различной геометрией и стилевыми токенами. При
визуальной приёмке также устранено пересечение footer-линии с ценой.

## Серверная модель подборки

Совместимая миграция `0022_project_collections` добавляет:

- `project_collections`: project_id, version, updated_at.
- `project_collection_items`: составной ключ project_id/offer_id, порядок,
  added_at, source_research_id и last_known для диагностики недоступного товара.

Уникальность — по точному SupplierOffer ID. На offer нет каскадного удаления:
если каталог перестал отдавать вариант, подборка сохраняет его и показывает
состояние. Создание нового snapshot с удалённым вариантом требует решения
пользователя; существующие документы не переписываются.

Миграция читает только `Project.active_query_id → ProjectQuery → ResearchRecord`.
Архивные selections не объединяются. Порядок активного выбранного списка
сохраняется; время миграции — время добавления в новую проектную коллекцию,
происхождение остаётся в source_research_id. Пустая коллекция считается уже
инициализированной, поэтому удалённые пользователем товары не воскресают.
В live-проверке два выбранных до миграции варианта перенеслись без потери.
Исключение исторических selections проверено отдельной постоянной регрессией.

Основные операции:

| Метод | Маршрут | Семантика |
|---|---|---|
| GET | `/api/projects/{id}/collection` | Полный выбор независимо от поиска/страницы |
| POST | `/api/projects/{id}/collection/items` | Идемпотентно добавить offer_id |
| DELETE | `/api/projects/{id}/collection/items/{offer}` | Идемпотентно убрать вариант |
| POST | `/api/projects/{id}/collection/clear` | confirmed=true и совпадение version |

Изменения сериализуются блокировкой строки проекта PostgreSQL; локальный lock
покрывает SQLite-тесты. Add/remove не отправляют полный устаревший массив.
Frontend хранит только очередь незавершённых операций и их optimistic проекцию.
Ответ с меньшей версией или от прежнего проекта игнорируется. Focus/периодическое
чтение согласует вкладки. Ошибка откатывает неподтверждённое действие и видна
внутри modal-панели с повтором, а не за её backdrop. Повтор очистки после
конфликта заново читает состояние и требует подтверждения нового количества.

Создание документа ждёт завершения операций и проверяет collection_version под
тем же project lock. В snapshot попадает весь сохранённый порядок. Изменение
подборки не меняет существующий документ. Композиционный refresh создаёт новую
версию, сохраняет подписи прежних позиций и добавляет новые snapshot-данные.
Ownership проверяется на каждой операции и всех маршрутах PDF/preview/assets.

## Общие компоненты и три направления

Путь один: `Collection snapshot → DesignPlan → ReportLab PDF → PDFium preview`.
Шрифты, фоновые маски, Decimal-цены, безопасность файлов и очередь остаются
существующими. Установка и лицензии — [presentations.md](presentations.md).

| Стиль | Геометрия и характер |
|---|---|
| Editorial | Открытая бумага, асимметричная пара, разный масштаб вариантов, крупная типографика |
| Premium Dark | Чередование тёмных/светлых страниц, hero с предметом справа, сдержанные линии и контрастные области только при необходимости |
| Modern Graphic | Светлая обложка с цветовой плоскостью, модульные линейки, другой масштаб/положение вариантов, крупные номера страниц |

`PagePainter`, общие photo/caption/price/logo/footer/text-bound проверки и один
renderer используются во всех стилях. Геометрия вариантов задаётся конфигурацией,
а hero, asymmetric, variants, lineup и category — отдельные общие композиции.
Переход категории выполняет заголовок следующей товарной страницы; пустые
разделительные страницы не добавляются ради разнообразия. Нет трёх копий PDF-движка.

Вместо трёх страниц исходного Melango PDF получены обложка и одна сравнительная
страница трёх вариантов. Underlying IDs, цвета, фотографии и цены не объединены.
Для длинных названий используется hero. Палитра влияет на оформление, не на
фильтры/цвет фотографий. Контраст текста учитывает и промежуточные серые палитры.

## Локальный AI-планировщик

Используется существующая Ollama/Qwen3:4b и её bounded queue, concurrency и
schema completion. Установленная модель публикует completion/tools/thinking,
не vision. После подготовки фото worker передаёт родительскому API размеры,
aspect ratio и alpha-признак; API делает один ограниченный запрос, без БД-транзакции.
Фотографии и клиентский логотип модели не передаются. В запросе нет цен, SKU,
source URLs, имени клиента или всего каталога.

Pydantic DesignPlan содержит style/version, seed, palette_order и страницы с
layout, product_refs, нейтральным heading и разрешённым motif. Decoding schema
ограничивает product_refs enum точных выбранных offer IDs. Parent ID — только
группировочные данные. Сервер повторно проверяет все ID ровно один раз вне
обложки, отсутствие лишних/потерянных товаров, плотность, связь вариантов,
длинный текст, заголовок страницы, палитру, seed и выбранный стиль. Коммерческие
поля renderer читает исключительно из snapshot. Код, внешние URL, SQL и shell
не входят в грамматику плана и не исполняются.

План сохраняется в revision до рендера; retry использует сохранённый план.
Ожидание ограничено `PRESENTATION_DESIGN_TIMEOUT_SECONDS=25` (допустимо 1–60).
Генерация без модели работает детерминированно. В result сохраняются реальные
ai_used, fallback_reason и ai_seconds; UI объясняет fallback понятным текстом.

В ранних live-запусках получены два тайм-аута около 25 s; PDF завершился через
fallback с ai_used=false. Отдельный ответ Qwen ошибочно сослался на parent ID:
он был отклонён. После variant-enum schema и допустимого baseline-плана реальные
ревизии дали ai_used=true за **3.877 s** и **4.386 s**. Первый ответ сохранил
базовую композицию — новизна ему не приписывается. «Другой вариант» с seed=1
выбрал пару и hero: три страницы вместо двух, те же три offer IDs.
Invalid DesignPlan и timeout дополнительно проверены постоянными тестами;
fallback не выдаётся за успешную работу AI.

## Сохранность и воспроизведение

До/после: **4371 SupplierOffer**, fingerprint коммерческих offer/observation
данных `b64e9d7dfb7cc8b653d9389f8cd6e4dc` одинаковый. Проверены также fingerprints
двух существовавших до теста пользовательских черновиков — без изменений.
VTO job `3af11531-88ce-4c5f-b33d-869c4045d606` сохранил checkpoint page 22;
его собственный backoff TEMPORARILY_UNAVAILABLE не относится к презентациям.
Ни каталог, ни observations, аккаунты, пользовательские PDF, snapshots или
checkpoints не сбрасывались. Маски и оригиналы остаются в управляемом storage.

Для обновления установленного проекта достаточно существующего `alembic upgrade head`
и перезапуска API/frontend после build. Настройки Qwen остаются общими с поиском;
при недоступной модели выбранный стиль работает без AI.

`scripts/check_collection_design.py`: prepare → chain → design → осмотр страниц →
approve --reviewed → logo → verify → cleanup. Ledger содержит точные disposable
IDs и cookies, не печатается и не коммитится. Cleanup удаляет только эти ресурсы
и task-owned render directories. Постоянные tests, skill, эталоны и реальные
пользовательские документы сохраняются.

Очистка выполнена: SQL подтвердил 0 аккаунтов `collection-v2-*`, 4371 offer и
две исходные ревизии NEEDS_REVIEW. Удалены временные render directories,
ledger/cookies, probes, screenshots и отдельный профиль Edge. Дополнительно
выполнен свежий prepare/cleanup постоянного acceptance script. API `/api/health`,
frontend и его health proxy после очистки вернули HTTP 200. PostgreSQL, Ollama,
API и frontend работают; временный browser debugging listener закрыт.
