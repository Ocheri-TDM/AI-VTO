# Категории запроса: скрытие, показ и удаление

31 октября 2026. Реализовано в существующей unified grid. Проверено на основной
PostgreSQL, HTTP API и установленном Edge. Новых режимов, диалогов поиска,
миграций и браузерных зависимостей нет.

## Серверный источник категорий

Плашки — проекция сохранённых `ResearchIntent.branches`, а не разбор строки на
frontend или категории первой страницы. Ветка содержит стабильный UUID,
canonical concept, label, исходный фрагмент, порядок, локальные цвет, модель,
бренд, материал, цену и количество. У старых записей ID детерминированно
восстанавливается из research ID и позиции; при изменении сохраняется в JSON.

Сервер возвращает `query_categories` с русским названием, ID, исходным текстом,
constraints, count и hidden. Порядок соответствует запросу, в том числе
`ручки бутылки рюкзаки` без разделителей. Две ветки ручек с разными моделями или
условиями имеют разные ID. Повтор одинаковой ветки не создаёт дубликат.
Нормализованные названия не подменяют сохранённый исходный фрагмент.

Неизвестная явно запрошенная позиция остаётся со статусом «Категория не
распознана», source_text и нулём результатов. Известная категория с нулём
подходящих товаров сохраняет нормальное имя. Для открытой категории наличие
каталожного evidence проверяется отдельно от коммерческих фильтров: нулевой
остаток не означает нераспознанную категорию. При этом неподтверждённая позиция
не запускает поиск всего каталога.

Бренды, модели и атрибуты не создают отдельных плашек. У Tippo одна категория
ручек и обязательная модель. У самостоятельного Molti — «Категории не ограничены»;
категории найденных товаров не превращаются в плашки.

## Скрытие и изменение плана

Все действия идут через существующий `PATCH /api/researches/{id}/view` с version
и `branch_actions`. У каждого действия известны branch_id и тип операции.
Для них не вызываются Query Understanding, Qwen или VTO. Это проверено отдельной
регрессией с запрещённым query resolver.

Пример тела:

```json
{
  "version": 3,
  "branch_actions": [{"action": "hide", "branch_id": "saved-branch-uuid"}]
}
```

`hide` / `show` меняют только `ResearchView.hidden_branch_ids`. Intent,
исходное сообщение и все условия сохраняются. Скрытая плашка остаётся доступной,
получает состояние «Скрыта» и отдельную кнопку показа. `show_all` очищает только
видимость; фильтры, удалённые ветки и выбранные товары не меняются. Сброс
дополнительных фильтров также не стирает сохранённую видимость.

`remove` исключает ровно указанную ветку, сохраняет остальные и создаёт обычную
ревизию с прежними intent/view в существующем history. Локальные дополнительные
условия удаляются, когда больше не относятся к оставшейся ветке. Глобальные
условия сохраняются. Заголовок строится из effective plan; оригинальный запрос
в истории не переписывается.

Контекстное «Категория … убрана. Вернуть» использует removal ID из этой же
истории. Восстанавливаются UUID, порядок и локальные условия, включая прежнюю
видимость. Более поздние изменения других фильтров не откатываются. Стабильный
порядок работает и при нескольких удалениях: восстановление B при отсутствующей
A не переставляет C. Старые intent/view snapshots не переписываются. После
чат-команды «назад» контекстное восстановление снова доступно; superseded token
не может воскресить старую версию ветки. История остаётся ограниченной прежним
окном 30 записей; просроченное восстановление возвращает понятную ошибку.

Отдельной общей кнопки «Отменить» и второго undo-хранилища нет. Исходные сообщения
и команды сохраняются в research и истории чата.

## Выдача, счётчики и сохранность выбора

- `base_total` / `pool_count` — полный активный поисковый пул.
- `eligible_total` — после дополнительных товарных фильтров, до скрытия.
- `visible_total` / `filtered_total` / `matching_count` — видимый итог.
- `products.length` — загруженная страница; размер по-прежнему максимум 100.

Плашки считают полные подходящие ID после товарных фильтров. Скрытие не обнуляет
их счётчики. В сетке один offer остаётся, пока подходит хотя бы одной видимой
ветке со всеми её условиями. Общий итог — объединение ID, не сумма счётчиков.
Ручка-карандаш после скрытия ручек остаётся по карандашам; порядок и подпись
карточки следуют первой оставшейся подходящей ветке. Зонт с ручкой не становится
пишущей ручкой. Пересечение гарантированно проверено независимыми fixtures.

Полные пулы остаются на backend. По всему пулу читаются скалярные SQL-проекции;
Product DTO гидратируются только для страницы и выбранных товаров. Frontend не
загружает все страницы ради плашек и не прячет результаты через CSS.

При скрытии всех веток: «Все категории скрыты» и «Показать все». При удалении
последней: «В запросе не осталось категорий», контекстное восстановление и
возможность нового запроса. Оба случая возвращают ноль карточек. Отдельный
brand-only поиск сохраняет явно неограниченные категории.

Проектная коллекция остаётся самостоятельным источником выбора. Изменение ветки
не вызывает её replace/clear/remove. Счётчик «Вне текущей выдачи» сравнивает выбор
с полным видимым ID-набором. Документы и snapshots не обновляются.

## Согласование UI, чата и конкурентных запросов

Плашки размещены над фильтрами в прежней левой части HUD. Измеренное desktop
соотношение с правой подборкой — 4.00:1, перекрытия нет. Есть отдельные кнопки
глаза и удаления, title, доступные имена, текст «Скрыта», перенос и мобильные
touch targets. У похожих веток ограничения входят в подпись и accessible name.

Работают команды «Скрой бутылки», «Покажи бутылки снова», «Убери бутылки из
запроса», «Добавь ежедневники», «Покажи все категории». Последняя не отменяет
товарные фильтры и не возвращает удалённые категории. Новые ветки видимы.
Новый standalone поиск начинает с пустым hidden state; история восстанавливает
сохранённое состояние конкретного исследования.

Используются прежние ownership, advisory lock, version и revision. Быстрые
операции сохраняются упорядоченной пачкой; они не перетираются последним кликом.
Category generation инвалидирует cursor даже после hide/show roundtrip, не ломая
пагинацию при простом изменении выбора. После конфликта 409 writer перечитывает
сервер и повторяет актуальное действие один раз. Ошибка откатывает локальную
проекцию. Сохраняются generation/revision guards для старых страниц, SSE и
ответов прежнего проекта. Focus согласует вкладки с актуальным поиском проекта.

разделителей при защите брендов/моделей; ведущий бренд больше не переносится
на соседние категории. Прежний глобальный trailing-brand сценарий сохранён.

Два клиента с одной version одновременно меняют разные ветки: один 200, другой
409; нет молчаливой потери записи. Чужому пользователю PATCH и collection GET
возвращают 404. После реального перезапуска API восстановлены active query ID,
все UUID/условия, BLACK, скрытая ветка и выбор.
