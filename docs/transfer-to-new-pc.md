# Перенос Souvenir Studio / AI-VTO на другой ПК

## Восстановление из готового ZIP

Архив предназначен для Windows x64. В него включены исходники текущей рабочей
копии, история Git, локальные настройки, логическая резервная копия PostgreSQL,
документы/логотипы/ключ публикации, Python 3.12, закреплённые Python wheels,
Node.js, зависимости frontend, PostgreSQL 17, Ollama и скачанные модели.

1. Скопируйте ZIP на новый ПК. Для переноса файла больше 4 ГБ нужен диск
   NTFS/exFAT, не FAT32. Желательно иметь не менее 20 ГБ свободного места для
   архива, распаковки, окружения Python, восстановленной БД и сборки frontend.
2. Распакуйте **всю** папку `AI-VTO` в новый короткий путь, например
   `C:\Projects\AI-VTO`. Не распаковывайте поверх другой работающей копии.
   Не теряйте скрытые `.env`, `.migration` и `.local`.
3. Откройте `AI-VTO\restore-project.bat`. Скрипт создаст новое окружение Python
   из включённого runtime, установит зависимости из локальных wheels без сети,
   инициализирует новый локальный PostgreSQL и восстановит dump. Количество и
   отпечатки всех таблиц, документы и ключи публикации будут проверены до запуска.
4. После подготовки скрипт автоматически вызовет обычный `start-project.bat`.
   Первая сборка frontend может занять несколько минут. Откройте
   <http://127.0.0.1:3000> и войдите с прежним именем и паролем.

**Дальнейшие запуски:** двойной щелчок по `start-project.bat`.
`restore-project.bat --prepare-only` только восстанавливает данные и окружение,
не запускает приложение. Повторный restore с совпадающей receipt не
переимпортирует БД. При наличии другого или неполного `postgres-data` скрипт
останавливается, ничего не стирая. Если первый restore оборвался, сохраните
папку неудачной попытки и повторите из новой полной распаковки ZIP.

## Что должно работать

| Сервис | Локальный адрес |
|---|---|
| Frontend | `http://127.0.0.1:3000` |
| FastAPI | `http://127.0.0.1:8000/api/health` |
| PostgreSQL | `127.0.0.1:55432`, БД `souvenir` |
| Ollama | `http://127.0.0.1:11434` |

Ngrok не входит в запуск. Порты должны быть свободны от другой копии проекта.
В консоли обычного launcher отображается время, HTTP-метод, длительность,
Name и Id пользователя. Закрытие этой консоли завершает просмотр журнала,
а не сервисы (см. [run-project.md](run-project.md)).

Архив сохраняет каталог, поисковую историю, пользователей, проекты, подборки,
предложения, публикации, сроки их действия, уведомления, импорт и checkpoints
на момент выгрузки, а не синхронизирует их между компьютерами. Импорт после
обычного запуска продолжает работать по прежним настройкам. Не запускайте
одновременно обе рабочие копии как одну production-систему: их БД независимы.
Скопированные публичные ссылки сохраняют ключи и прежние сроки действия.
Их доступность по старому внешнему домену требует отдельной настройки адреса
backend/развёртывания; она не переносится автоматически.

Обычный локальный поиск и восстановление уже сохранённых данных не требуют
скачивания Python-пакетов, Node-пакетов или моделей. Интернет нужен для
обновления VTO, загрузки ещё не сохранённых фото и внешних публикаций.
Производительность Ollama зависит от CPU/GPU нового ПК. При ошибке загрузки
системной DLL может потребоваться штатный Microsoft Visual C++ Redistributable x64.
Архив не предназначен для macOS, Linux или Windows ARM без отдельной адаптации.

## Важно о данных

Это **приватная резервная копия** реальной базы и файлов, а не публичный релиз.
В ZIP есть `.env`, хеши паролей, документы пользователей и ключ публикации.
Архив не зашифрован. Храните и передавайте его только доверенным получателям.
Сохраните ZIP и контрольную SHA-256; браузерные cookies, чужие профили браузера,
кэш старого `.venv`, `.next`, временные acceptance-файлы и рабочий физический
`postgres-data` не переносятся. Пользователи входят заново своими паролями.

## Если запуск не удался

- Проверьте, что весь архив распакован, а не запущен прямо из ZIP.
- Не запускайте копию в папке с другим `postgres-data` и не используйте команды
  сброса БД. Исправляйте проблемы в отдельной новой распаковке.
- При ошибке restore проверьте сообщение в консоли и `.local/restore-postgres.log`.
- При ошибке frontend/API смотрите `.local/web-build-launcher.log`,
  `.local/web-launcher.log`, `.local/api-launcher.log`.
- Проверьте контрольную сумму ZIP, если часть файлов не читается после копирования.

## Создание нового архива в будущем

Из существующего проекта с подготовленными portable runtimes и зависимостями
сначала остановите API, frontend и фоновые workers. PostgreSQL должен быть
доступен локально. Запустите из корня:

```powershell
.\.venv\Scripts\python.exe scripts/create_transfer.py --output "C:\AI-VTO-backups\transfer-new"
```

Нужна сеть для получения exact Python wheels при создании нового архива.
Экспорт использует согласованный PostgreSQL snapshot и не изменяет источник.
Выходная папка должна быть новой и находиться вне исходного репозитория.
Файлы новой рабочей копии не нужно коммитить в Git.
